Antigravity Launcher Lite 1.0.1 新增客户端更新后自动恢复代理，减少更新完成后手动退出、重新启动的操作。

### 本次更新

- 设置中新增“更新后自动恢复代理”开关，默认关闭，保存后下次打开启动器仍会记住。
- 开启后，通过启动器打开 Antigravity。启动器在后台跟踪这次会话，关闭启动器窗口后仍可工作。
- 发现安装文件内容变化、原进程退出且新主进程稳定运行后，先检测原代理，再请求客户端正常退出，随后带本次启动时的代理重新打开。
- 遇到未保存提示请先处理；正常退出未完成时等待，超过两分钟停止自动恢复，不强制结束进程。普通退出、未更新的重启不会自动拉起客户端。
- 修正 Windows 普通路径与规范路径前缀差异导致的进程匹配问题。
- 关闭开关会取消尚未执行的恢复步骤；已经送达客户端的退出请求无法撤销。完全退出启动器后不再监测。

### 下载与升级

| 系统 | 安装包 |
| --- | --- |
| macOS · Apple Silicon | `macos-arm64.dmg`，另附 `.app.zip` |
| macOS · Intel | `macos-x64.dmg`，另附 `.app.zip` |
| Windows · x64 | `windows-x64-setup.exe`，默认安装到当前用户 |
| Linux · x86_64 | `linux-x64.deb` / `linux-x64.AppImage` |

所有文件均带 `Antigravity-Launcher-Lite_1.0.1_` 前缀。退出旧启动器后安装新版；客户端路径、代理、语言与主题设置会保留。打开“设置”，开启新开关，再从启动器打开客户端即可。

附 `SHA256SUMS.txt` 和 `BUILD-METADATA.json`，可核对安装包哈希、架构和构建提交。

### 支持范围与验证

- 自动恢复只跟踪本次由启动器启动的会话，不接管其他已运行客户端，不修改系统全局代理或客户端用户设置。
- macOS 使用系统正常退出请求；Windows 使用窗口关闭消息；Linux 仅尝试 X11/EWMH。客户端不响应、出现多个主进程或路径身份无法确认时停止自动恢复，按界面提示处理。
- 原生 Wayland、AppImage 的临时挂载进程路径、更新后更换安装目录，尚不支持可靠的自动恢复。Linux 的 deb/AppImage 安装包仍保留原有手动检测与启动功能。
- 本机 macOS 已通过核心测试及独立 Cocoa 辅助应用的正常退出/拒绝退出测试；中英文设置与最小内容区域完成模拟 IPC 界面检查。真实 Antigravity 更新重启与未保存文件流程尚待实际更新验收，不将辅助程序测试等同于客户端验收。
- [三平台常规验证](https://github.com/Alisonispig/antigravity-launcher-lite/actions/runs/42144160123) 和 [四架构打包](https://github.com/Alisonispig/antigravity-launcher-lite/actions/runs/42144167171) 全部通过，包括原生安装包构建、架构/版本检查和安装/启动烟测。所有下载文件均与清单及 GitHub 资产 SHA-256 核对一致；构建提交为 `ba9e565b7c9fd216623ead472803c28d9f90e86a`。CI 烟测不等于最低系统版本或所有真实设备的完整兼容验收。

### 签名与运行环境

macOS 为 adhoc 本地签名，无 Developer ID 签名或苹果公证；Windows 未做 Authenticode 签名，系统可能提示。macOS 相关说明见 [Apple 官方帮助](https://support.apple.com/102445)。Windows 需要 WebView2，安装器会按需联网下载；Linux 仍需发行版图形栈、WebKitGTK/FUSE 等运行条件。

macOS 构建声明最低版本 11.0、构建环境为 macOS 15；Windows 使用 Windows Server 2022 构建，面向 Windows 10/11 x64；Linux 使用 Ubuntu 22.04 构建。不扩大最低系统版本兼容承诺。

本应用为独立开发的非官方工具，非 Google 出品，不包含 Antigravity 本体或代理服务。完整说明见 [README](https://github.com/Alisonispig/antigravity-launcher-lite#readme)。
